Part 4 · 04 · BACKground

Six properties that make a reservoir work

01 · stability

Echo state property

click for definition
echo state property
\bigl\| x_t(x_0^{A},u) - x_t(x_0^{B},u) \bigr\| \to 0

The state becomes a function of the input history alone: any two initial states wash out under the same drive.

[1] Lorem ipsum, Consectetur Adipiscing, 2001, Def. 1.
02 · continuity

Fading memory

click for definition
fading memory
u^{A}_{t-k}\!=\!u^{B}_{t-k}\ \forall k\le K \Rightarrow \|x^{A}_t - x^{B}_t\| < \varepsilon

The filter is continuous in a weighted-history norm: recent inputs dominate, distant ones decay smoothly.

[2] Dolor Sit & Amet, Sed Do Eiusmod, 1996.
03 · capacity

Memory profile

click for definition
memory capacity
MC=\sum_{k\ge1} m(k),\quad m(k)=\frac{\mathrm{cov}^2(u_{t-k},\hat{y}_t)}{\sigma^2_u\,\sigma^2_{\hat y}}

How well delay k can be linearly recovered from the state. Bounded by the number of readout observables.

[3] Tempor Incididunt et al., Ut Labore, 2002.
04 · expressivity

Separation

click for definition
separation property
u^{A}\neq u^{B} \;\Longrightarrow\; x(u^{A}) \neq x(u^{B})

Distinct input histories are mapped to distinguishable states — the feature map must not collapse them.

[4] Magna Aliqua, Enim ad Minim, 2004.
05 · access

Readout accessibility

click for definition
readout accessibility
\hat y_t = W_{\mathrm{out}}\,s_t,\quad s_t=\bigl(\langle O_i\rangle_{\rho_t}\bigr)_{i=1}^{M}

Only M measured observables reach the linear readout — the usable state, not the full state, sets performance.

[5] Veniam Quis, Nostrud Exercitation, 2017.
06 · guarantee

Universality

click for definition
universality
\forall\, F,\ \varepsilon>0\ \ \exists\, W_{\mathrm{out}}:\ \sup_{u}\|F(u)-\hat y(u)\|<\varepsilon

Fading memory plus separation make the reservoir family dense in the causal, time-invariant filters.

[6] Ullamco Laboris, Nisi ut Aliquip, 2018.

The dissipative quantum reservoir computing

1. Construct input-dependent Hamiltonian
H(u_t) = \sum_i h_i X_i + \sum_i J_i Z_i Z_{i+1} + u_t \sum_i w_i Z_i
2. unitary evolution
\rho \leftarrow U \rho U^{\dagger}, \qquad U = \exp\!\left(-i\,H(u_t)\,\tau\right)
3. Apply the dissipative step, where memory fades
\rho \leftarrow (1-\gamma)\,\rho + \gamma\,|0\ldots 0\rangle\langle 0\ldots 0|https://qiskit.github.io/qiskit-aer/stubs/qiskit_aer.noise.reset_error.html

Example: detecting failure with logs

Part 4 · 18

Take away from this use case from experiment tracking perspective

01

A reservoir's knowledge is its configuration

Nothing inside is trained. There is no weight file to fall back on. Unlogged parameters are lost science.

02

Log the four categories, not your favourites

Circuit, computer, compilation, execution. A difference in any one makes two runs incomparable, and three of the four are invisible in your source file.

03

Log what produced the data, not only the data

Cached intermediates are where quantum pipelines rot. Hash every generating parameter into the key and record the hash beside the result.

04

Tracking is a debugger, not paperwork

We found a real bug in ninety seconds from two logged runs. Nothing else in the toolchain could have found it at all.

05

Always report skill against a classical baseline

Persistence, seasonal-naive, and a leaky ESN with the same feature budget — logged in the same run, so the comparison is never assembled from memory.

06

The cost of starting is one pip install

There is no threshold of project size below which this is not worth it. The run you cannot reproduce is usually the first one.
